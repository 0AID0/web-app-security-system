Redis с TLS

Безопасное хранилище ключ-значение с шифрованием трафика

На главную

Обзор технологии

Redis с поддержкой TLS (Transport Layer Security) - это защищенная версия популярного хранилища ключ-значение, где весь трафик между клиентом и сервером шифруется.

Шифрование трафика

Все данные передаются по зашифрованному каналу, защищая их от перехвата.

Аутентификация

Сертификаты TLS обеспечивают проверку подлинности сервера и клиента.

Целостность данных

Гарантия, что данные не были изменены при передаче.

Конфигурация сервера Redis

# redis.conf
port 0
tls-port 6379
tls-cert-file /path/to/redis.crt
tls-key-file /path/to/redis.key
tls-ca-cert-file /path/to/ca.crt
tls-auth-clients yes # Требовать сертификаты от клиентов
Подробнее о параметрах
Ключевые параметры:
- tls-port: порт для TLS соединений
- tls-cert-file: сертификат сервера
- tls-key-file: приватный ключ сервера
- tls-ca-cert-file: корневой сертификат CA
- tls-auth-clients: требовать клиентские сертификаты

После настройки перезапустите Redis: redis-server /path/to/redis.conf

Подключение клиента с TLS

# Python пример с redis-py
import redis

r = redis.Redis(
  host='redis.example.com',
  port=6379,
  ssl=True,
  ssl_ca_certs='/path/to/ca.crt',
  ssl_certfile='/path/to/client.crt',
  ssl_keyfile='/path/to/client.key',
  ssl_cert_reqs='required'
)

# Тестирование соединения
print(r.ping()) # Должно вернуть True

Генерация сертификатов

# Генерация корневого CA
openssl genrsa -out ca.key 4096
openssl req -new -x509 -days 365 -key ca.key -out ca.crt

# Генерация сертификата сервера
openssl genrsa -out redis.key 2048
openssl req -new -key redis.key -out redis.csr
openssl x509 -req -days 365 -in redis.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out redis.crt

# Генерация клиентского сертификата
openssl genrsa -out client.key 2048
openssl req -new -key client.key -out client.csr
openssl x509 -req -days 365 -in client.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out client.crt

Проверка сертификата

Безопасность сертификатов
Рекомендации по безопасности:
1. Храните приватные ключи в безопасном месте
2. Используйте надежные пароли для ключей
3. Устанавливайте разумные сроки действия сертификатов
4. Регулярно обновляйте сертификаты
5. Отзывайте скомпрометированные сертификаты

Для production используйте сертификаты от доверенных CA (Let's Encrypt, DigiCert и др.)

Базовые операции с TLS

import redis

# Создание безопасного соединения
r = redis.Redis(
  host='secure.redis.example',
  ssl=True,
  ssl_ca_certs='ca.crt'
)

# Запись и чтение данных
r.set('user:1000:name', 'Алексей', ex=3600) # TTL 1 час
name = r.get('user:1000:name')
print(name.decode('utf-8')) # Алексей

# Хеши
r.hset('user:1000', mapping={
  'name': 'Алексей',
  'email': 'alex@example.com',
  'last_login': '2023-05-15T10:00:00'
})
user_data = r.hgetall('user:1000')
print(user_data) # {'name': b'Алексей', 'email': b'alex@example.com', ...}

Использование Pipeline с TLS

import redis

r = redis.Redis(ssl=True, ssl_ca_certs='ca.crt')

# Создание pipeline
pipe = r.pipeline()

# Добавление команд
pipe.set('counter', 0)
pipe.incr('counter')
pipe.incrby('counter', 10)
pipe.get('counter')

# Выполнение всех команд за один запрос
result = pipe.execute()
print(result) # [True, 1, 11, b'11']

Демонстрация Pipeline

Преимущества Pipeline
Почему использовать Pipeline:
- Уменьшает количество сетевых запросов
- Увеличивает производительность (до 5-10x)
- Все команды выполняются атомарно (одна транзакция)
- Особенно полезно при высоких задержках сети

Ограничения:
- Некоторые команды (например, WATCH) требуют особой обработки
- Большие pipeline могут блокировать сервер

Pub/Sub с шифрованием

import redis
import threading

# Функция подписчика
def subscriber():
  r = redis.Redis(ssl=True, ssl_ca_certs='ca.crt')
  pubsub = r.pubsub()
  pubsub.subscribe('notifications')
  for message in pubsub.listen():
    if message['type'] == 'message':
      print("Получено:", message['data'].decode())

# Запуск подписчика в фоне
thread = threading.Thread(target=subscriber)
thread.start()

# Публикация сообщений
r = redis.Redis(ssl=True, ssl_ca_certs='ca.crt')
r.publish('notifications', 'Сообщение 1')
r.publish('notifications', 'Сообщение 2')

Лучшие практики безопасности

Управление сертификатами

  • Используйте надежные ключи (минимум 2048 бит)
  • Регулярно обновляйте сертификаты
  • Отзывайте скомпрометированные сертификаты

Контроль доступа

  • Ограничьте доступ к Redis только доверенным клиентам
  • Используйте ACL (начиная с Redis 6)
  • Реализуйте двухфакторную аутентификацию

Настройки TLS

  • Используйте современные версии TLS (1.2 или 1.3)
  • Отключите устаревшие шифры
  • Настройте perfect forward secrecy
# Проверка настроек TLS (используя openssl)
openssl s_client -connect redis.example.com:6379 -starttls redis | openssl x509 -noout -text

# Проверка поддерживаемых шифров
nmap --script ssl-enum-ciphers -p 6379 redis.example.com
