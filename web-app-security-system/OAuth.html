Основы OAuth 2.0

OAuth 2.0 — это протокол авторизации, который позволяет приложениям получать ограниченный доступ к учетным записям пользователей на других сервисах без необходимости знать их пароли.

Ключевые роли в OAuth 2.0:

  • Resource Owner (Владелец ресурса) - пользователь, который владеет данными и может предоставить доступ к ним
  • Client (Клиент) - приложение, запрашивающее доступ к данным пользователя
  • Authorization Server (Сервер авторизации) - сервер, который аутентифицирует пользователя и выдает токены (например, Google OAuth, Facebook Login)
  • Resource Server (Сервер ресурсов) - API с защищенными данными пользователя, которые запрашивает клиент

В реальных реализациях Authorization Server и Resource Server часто являются частью одной системы, но концептуально это разные роли.

Основные термины:

  • Access Token - ключ для доступа к API, обычно JWT (JSON Web Token)
  • Refresh Token - долгоживущий ключ для обновления access token без участия пользователя
  • Authorization Code - временный код, который клиент обменивает на токены
  • Scope - набор разрешений, которые запрашивает клиент (profile, email, openid и т.д.)
  • Redirect URI - URL, на который сервер авторизации возвращает пользователя после подтверждения
  • Client ID/Secret - идентификатор и секрет клиента, выданные при регистрации приложения

Популярные провайдеры OAuth 2.0:

Google Facebook GitHub Twitter Microsoft LinkedIn Apple Amazon

Каждый провайдер может иметь свои особенности реализации OAuth 2.0, всегда проверяйте документацию.

Рекомендации по безопасности:

  • Всегда используйте HTTPS для всех OAuth-запросов
  • Храните client secret безопасно (не в клиентском коде)
  • Используйте PKCE (Proof Key for Code Exchange) для мобильных и SPA приложений
  • Проверяйте параметр state для защиты от CSRF-атак
  • Ограничивайте срок действия токенов
  • Используйте минимально необходимые scope

Authorization Code Flow

Самый распространенный и безопасный поток авторизации, рекомендованный для серверных приложений.

1

Клиент перенаправляет пользователя

Приложение отправляет пользователя на сервер авторизации с параметрами:

https://auth-server.com/authorize?
  response_type=code&
  client_id=CLIENT_ID&
  redirect_uri=https://app.com/callback&
  scope=profile+email&
  state=xcoiv98y2kd22vusuye3kch&
  code_challenge=CODE_CHALLENGE&
  code_challenge_method=S256
2

Пользователь авторизуется

Пользователь входит в систему и подтверждает запрошенные разрешения.

Приложение "DemoApp" запрашивает доступ:

  • Просмотр вашего профиля (имя, фото)
  • Доступ к вашему email адресу

Это приложение хочет получить доступ к вашему аккаунту example@domain.com

3

Сервер возвращает код авторизации

Пользователь перенаправляется обратно на указанный redirect_uri с кодом авторизации:

https://app.com/callback?
  code=AUTHORIZATION_CODE&
  state=xcoiv98y2kd22vusuye3kch
AUTHORIZATION_CODE=6e7a1b9c8d2e4f5a3b7c8d9e0f1a2b3

Срок действия: 10 минут

Код может быть использован только один раз

4

Клиент запрашивает токен доступа

Приложение делает POST-запрос к токен-эндпоинту, обменивая код на токены:

POST /token HTTP/1.1
Host: auth-server.com
Content-Type: application/x-www-form-urlencoded
Authorization: Basic BASE64(CLIENT_ID:CLIENT_SECRET)

grant_type=authorization_code&
code=AUTHORIZATION_CODE&
redirect_uri=https://app.com/callback&
code_verifier=CODE_VERIFIER
5

Сервер возвращает токены

Ответ сервера содержит access token и опционально refresh token:

Другие типы потоков

Implicit Flow

Упрощенный поток для клиентских приложений (SPA, мобильные). Токен возвращается сразу в redirect URI через фрагмент URL.

response_type=token
response_type=id_token

Не рекомендуется к использованию из-за меньшей безопасности.

Client Credentials

Для сервер-серверного взаимодействия без участия пользователя. Используется для машин-машинной аутентификации.

grant_type=client_credentials
scope=api.read

Не включает пользовательский контекст, только доступ для приложения.

Refresh Token

Обновление истекшего access token с помощью refresh token без повторной авторизации пользователя.

grant_type=refresh_token
refresh_token=REFRESH_TOKEN

Refresh tokens обычно имеют длительный срок действия (дни, месяцы).

PKCE (RFC 7636)

Дополнительная защита для Authorization Code Flow в нативных и SPA приложениях.

code_challenge=CODE_CHALLENGE
code_challenge_method=S256

Защищает от атак с перехватом кода авторизации.

Resource Owner Password

Прямая передача учетных данных пользователя (логин/пароль) для получения токена.

grant_type=password
username=USERNAME
password=PASSWORD

Используйте только для доверенных приложений (официальные клиенты).

Device Flow

Для устройств с ограниченными возможностями ввода (Smart TV, IoT).

grant_type=urn:ietf:params:oauth:grant-type:device_code

Пользователь авторизуется на другом устройстве с полным браузером.
